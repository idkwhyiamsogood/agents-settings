# Инструменты, skills и автоматизация

- Выбирать доступные средства под задачу и формат. Не считать пути, временные
  скрипты, плагины и программы из прошлой сессии доступными в новом проекте.
- Для связанного документа предпочитать подходящий подключённый инструмент,
  если он покрывает задачу. Для локальных файлов допустимы пакетные средства.
- DOCX: python-docx — структура/стили; zipfile и lxml — точечные правки Open XML
  с сохранением отношений и вложений. Выбирать способ по риску потери свойств.
- draw.io MCP и движок draw.io/mxGraph — редактирование и экспорт моделей;
  headless Chromium может использоваться для экспорта, если доступен и разрешён.
- rsvg-convert или аналог — SVG в PNG; Pillow — размеры и контактные листы
  для проверки, а не перерисовка схем.
- ONLYOFFICE x2t, LibreOffice или доступный офисный движок — проверочный рендер;
  отдельный временный рабочий каталог для каждого запуска.
- Poppler pdftotext/pdftoppm или аналог — извлечение текста и просмотр страниц.
  Считать результат конкретного рендера проверкой этого движка, не гарантией
  идентичного отображения во всех приложениях.
- rg — поиск; Git — история и восстановление; веб-поиск — проверка внешних
  источников. Для иных форматов выбирать соответствующие средства.
- Применять skill только при реальной применимости или явном запросе.
  Сначала прочитать SKILL.md и сообщить об использовании. Не называть
  инструмент, Markdown-правило или обычный скрипт установленным skill.
- Не подключать imagegen, Figma или Sites лишь из-за слова «картинка».
  Для схем учитывать diagrams.md; для иных визуальных задач выбирать подходящий skill.
- Соблюдать разрешения среды. Не менять глобальные настройки, не устанавливать
  зависимости и не выполнять внешние действия сверх авторизованной задачи.
