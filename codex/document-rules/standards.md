# Стандарты и формальные нотации

- Подбирать стандарты по типу материала, предмету, юрисдикции и заданию.
  Не применять весь каталог ниже к каждому проекту.
- Перед нормативным изменением читать нужные положения, проверять редакцию,
  область применения и статус по первоисточнику. Для российских стандартов
  предпочитать официальный каталог Росстандарта: https://protect.gost.ru/.
- Различать обязательное требование, договорённость проекта и рекомендацию.
  При содержательном конфликте образца, задания и стандарта явно обозначать
  расхождение, не приписывать образцу нормативную силу.
- Не называть настройки шаблона требованиями ГОСТ. Не заявлять полное
  соответствие стандарту по одному упоминанию или проверке отдельных пунктов.

## Справочный каталог

Это отправные точки для выбора, а не автоматически обязательные документы:

| Источник | Возможная область применения |
| --- | --- |
| ГОСТ 34.602-2020 | Содержание технического задания на автоматизированную систему. |
| ГОСТ 34.201-2020 | Виды, комплектность и обозначение документации автоматизированных систем. |
| ГОСТ Р 59795-2021 | Содержание документов автоматизированных систем. |
| ГОСТ 7.32-2017 | Структура и оформление отчёта о научно-исследовательской работе. |
| Р 50.1.028-2001 | Рекомендации по функциональному моделированию IDEF0; это не ГОСТ. |
| NIST FIPS PUB 183 (1993) | Историческое описание IDEF0; не объявлять его действующим обязательным стандартом. |
| OMG UML 2.5.1 | Спецификация структурных и поведенческих UML-моделей; это не ГОСТ. |

Первоисточники нотаций:
https://www.omg.org/spec/UML/2.5.1/;
https://nvlpubs.nist.gov/nistpubs/Legacy/FIPS/fipspub183.pdf.
ER-модель сверять со словарём данных и ограничениями связности; выбранную
ER-нотацию обозначать явно. Не приписывать ей стандарт без основания.
Если проект требует иных стандартов, проверить их отдельно; не выдавать
новые ссылки за ранее применённые или уже проверенные.
