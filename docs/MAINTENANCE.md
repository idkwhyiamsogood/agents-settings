# Сопровождение

1. Изменять исходник в репозитории, а не экспортировать весь профиль устройства.
2. Постоянное требование помещать в правила соответствующего агента. Отдельную
   процедуру с понятным условием запуска — в `skills/<name>/SKILL.md` с полями
   `name` и `description`. Подробности подключать из references по необходимости.
3. Не дублировать skill для разных клиентов. Устанавливать обычные копии из
   единственного источника; проверять обнаружение в используемой версии клиента.
4. Пользовательские изменения стороннего skill обозначать рядом с источником;
   сохранять авторство и лицензионные файлы. При обновлении сравнивать изменения,
   а не заменять локальную адаптацию без проверки.
5. Не добавлять абсолютные пути устройства, crash IDs, trust записи, секреты,
   аккаунты, системные skills, кэш и сохранённые разрешения команд. Примеры
   команд должны быть явно помечены как зависящие от выбранного инструмента.
6. Проверить JSON, frontmatter skills, ссылки на ресурсы и preview установщика.
   При изменении установщика проверить отсутствие записей в preview,
   повторную установку и отказ при конфликтах в отдельном временном каталоге.
7. Устанавливать обновления по `INSTALL.md`; существующие отличающиеся настройки
   объединять с резервной копией. Для отката восстановить затронутые файлы из неё.

Старые `manifest.json`, `skill-links.json` и `export_settings.py` убраны:
они описывали машинный снимок и больше не соответствуют переносимой модели.
Пустой MCP-шаблон Claude сохранён только как указание формата, установщик его не
копирует. Прежние активные подключения на устройствах этот репозиторий не удаляет.
