# План установки для ИИ-агента

Этот файл можно передать агенту вместе с репозиторием: «Установи нужные мне
компоненты по этому плану». Агент объясняет действия простыми словами,
выполняет доступные шаги и сообщает конкретные препятствия.

## Последовательность

1. **Определить состав.** Проверить, какие из Codex, Claude Code, Cursor и VS Code
   уже установлены и какие нужны пользователю. Не устанавливать все четыре
   автоматически. Выяснить, нужны ли Figma, упаковка репозиториев и плагины.
2. **Подготовить средства установки.** Нужен Python 3.10+ только для скрипта
   этого репозитория; без него допустимо ручное копирование. Git нужен для
   клонирования и обновлений; можно скачать архив. Выбрать доступную команду
   запуска Python по среде, проверить её версию. Обозначение `PYTHON` в примерах
   ниже нужно заменить найденной командой, это не переменная окружения.
3. **Установить выбранные приложения** по их официальной инструкции для
   текущей платформы. Сначала проверить поддержку выбранной версии и поверхности
   приложения. Войти в аккаунты средствами приложений. Не переносить OAuth и токены.
4. **Найти реальные каталоги назначения.** Использовать интерфейс, диагностику
   и документацию установленного приложения. Для Codex учитывать CODEX_HOME;
   для редакторов — активный профиль, portable-режим и переопределения каталогов.
   Каталог skills проверять отдельно: он не обязан совпадать с конфигурационным.
   Не вычислять пути по ОС и не брать их с компьютера автора репозитория.
5. **Составить план копирования.** Для каждого выбранного компонента выполнить
   preview. В качестве DESTINATION подставить найденный каталог в кавычках:

   ```text
   PYTHON scripts/install.py --component codex-rules --destination "DESTINATION"
   ```

   | Компонент | Что означает DESTINATION |
   | --- | --- |
   | `codex-rules` | Каталог глобального AGENTS.md Codex; модули будут рядом |
   | `codex-config` | Каталог config.toml Codex; файл необязателен, содержит лишь комментарии |
   | `claude-rules` | Каталог глобального CLAUDE.md Claude Code |
   | `skills` | Поддерживаемый каталог пользовательских skills выбранного агента |
   | `cursor-user` | Активный каталог User/профиля Cursor |
   | `vscode-user` | Активный каталог User/профиля VS Code |

6. **Разрешить конфликты.** Существующие отличающиеся файлы скрипт не меняет;
   весь выбранный компонент блокируется до записи. Сохранить внешнюю резервную
   копию изменяемой конфигурации, объединить нужные поля вручную. Для этого можно
   установить компонент в отдельный временный каталог и сравнить файлы.
   Для JSONC использовать редактор/парсер с поддержкой комментариев; не удалять
   чужие ключи, bindings и snippets. Для skills можно копировать только нужные
   подкаталоги вручную, вместе со всеми references и сведениями об источнике.
7. **Применить готовый план.** Повторить команду с `--apply`. Скрипт использует
   только стандартную библиотеку Python, не скачивает пакеты, не меняет PATH
   и не создаёт symlink. Для каждого приложения запуск отдельный. Файлы с
   совпадающим содержимым пропускаются. Обновления отличающихся файлов объединять
   по шагу 6; автоматического удаления старых файлов нет.
8. **Установить дополнительные зависимости** только для выбранных функций,
   по таблице ниже. Подключения и команды MCP добавлять средствами конкретного
   приложения по его текущей схеме. Пустые MCP-шаблоны не являются подключениями.
9. **Проверить результат.** Перезапустить приложение; проверить обнаружение
   правил и skills. Проверить форматирование файла выбранного языка; для Figma
   получить успешный ping и подключённую сессию; для Repomix упаковать небольшой
   тестовый каталог без секретов. Плагины проверить в интерфейсе приложения.
10. **Сообщить итог.** Перечислить установленное, пропущенное, результаты проверок
    и оставшиеся действия пользователя. Не объявлять авторизацию или работу
    интеграции подтверждённой без проверки.

## Дополнительные зависимости

| Возможность | Что установить и в каком порядке |
| --- | --- |
| Только правила и настройки | Выбранное приложение; дополнительные runtimes не нужны |
| Figma-skills | Поддерживаемый runtime из документации Figwright → MCP Figwright в агенте → Figwright plugin в Figma → открыть plugin → ping → skill |
| Repomix | Поддерживаемый Node.js/runtime → Repomix по официальной инструкции → проверить CLI/интеграцию → skill |
| Форматирование JS/TS/JSON/CSS | Расширение `esbenp.prettier-vscode`, зависимости проекта по его инструкции |
| PHP | Расширение `bmewburn.vscode-intelephense-client` и среда проекта |
| Python в VS Code | `ms-python.python`, `ms-python.autopep8`; интерпретатор выбрать локально |
| Rust в VS Code | `rust-lang.rust-analyzer` и toolchain проекта |
| C# в VS Code | `ms-dotnettools.csharp` и SDK проекта |
| Sites, visualize, work-pets и другие плагины | Выбранный плагин через поддерживаемый каталог приложения → разрешения/аккаунт → проверка инструмента |
| Работа с офисными документами | Инструменты из `codex/document-rules/tools.md` выбирать под конкретную задачу; весь список заранее не устанавливать |

Если язык не нужен, удалить соответствующий formatter из локальных настроек
либо оставить его неактивным. Команды запуска MCP разрешать средствами приложения:
универсальная строка запуска не гарантируется всеми клиентами и платформами.
Версии зависимостей выбирать по текущей документации и требованиям проекта,
затем фиксировать локально; исторические версии кэша не являются требованиями.
